# Демо Jupyter для ЗУП КОРП 3.1.38.92

[01-overview.ipynb](01-overview.ipynb) показывает выбор сотрудников, плановый ФОТ, одну точку останова и hot reload типового метода. [03-capture.ipynb](03-capture.ipynb) исследует временную таблицу и стек вызовов между двумя точками останова, затем меняет локальный запрос только в одном вызове. Каждый notebook запускается сверху вниз в отдельном kernel.

Сценарии рассчитаны на выделенную демобазу **ЗУП КОРП 3.1.38.92**, платформу **8.5.1.1529** и выгрузку исходников этой же конфигурации. Дата данных в примерах — **01.08.2021**; это не номер релиза. 13.09.2026 оба notebooks прошли сверху вниз на файловой и клиент-серверной демобазах. На файловой ИБ использовался `ExtensionMode.AUTO`, на серверной — `ExtensionMode.MANUAL` с уже установленным совместимым расширением. При проверке hot reload менялась только отдельная локальная копия двух BSL-модулей; исходная выгрузка не менялась. Результаты выполнения остаются локальными и не входят в репозиторий.

Из корня репозитория установите окружение и зарегистрируйте kernel:

```powershell
uv sync --group dev
uv pip install --python .venv/Scripts/python.exe "jupyterlab>=4.1,<5" "matplotlib>=3.11,<4"
.venv/Scripts/python.exe -m ipykernel install --user --name onec-demo --display-name "1C BSL Demo"
.venv/Scripts/python.exe -m jupyterlab notebooks/demo
```

В стартовой Python-ячейке каждого notebook задайте `PLATFORM_BIN`, `CONNECTION_STRING` и `SOURCE_ROOT` для своей демобазы. В примере указано имя пользователя `Савинская З.Ю. (Системный программист)` с пустым паролем; при необходимости измените параметры `RuntimeConfig`. До запуска capture убедитесь, что `SOURCE_ROOT` содержит `CommonModules/КадровыйУчет/Ext/Module.bsl` из этой же версии конфигурации. Notebook находит строки двух точек в выгруженном методе и ставит их через `runtime.add_capture_point()`.

Для файловой ИБ по умолчанию используется `EXTENSION_MODE = ExtensionMode.AUTO`. Если в клиент-серверной ИБ расширение из этого релиза уже установлено и применено вручную, задайте `EXTENSION_MODE = ExtensionMode.MANUAL`: это позволяет начать сеанс без учётных данных Конфигуратора для автоматического обновления расширения. Режим `MANUAL` проверяет совместимость расширения при запуске.

Сценарии читают данные и меняют только состояние интерактивного сеанса. Используйте отдельную копию ИБ: установка runtime-расширения меняет её служебные данные. Последняя ячейка вызывает `runtime.close()`; после прерванного прогона вызовите его вручную перед новым запуском.

Исходные ячейки обоих notebooks находятся в `tools/build_demo_notebooks.py`. После изменения генератора выполните `uv run python tools/build_demo_notebooks.py` и проверьте, что сохранённые notebooks не содержат outputs.
