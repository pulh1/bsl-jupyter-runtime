# Демо Jupyter для ЗУП КОРП и УТ

[ZUP/01-overview.ipynb](ZUP/01-overview.ipynb) ведёт от `Привет, мир!` и состояния между BSL-ячейками к типовым данным ЗУП, pandas, материализации документа, hot reload и остановленному проведению `ПриемаНаРаботу`. В финале он проверяет значение оклада в регистре периодических показателей и показывает плановый ФОТ. [ZUP/03-capture.ipynb](ZUP/03-capture.ipynb) отдельно исследует временную таблицу и стек вызовов между двумя точками останова, затем меняет локальный запрос только в одном вызове. Каждый notebook запускается сверху вниз в отдельном kernel.

[UT/05-ut-sales.ipynb](UT/05-ut-sales.ipynb) — отдельный сценарий для **УТ 11.6.1.61**: сравнение месячной выручки из регистра «Выручка и себестоимость продаж», диаграммы по подразделениям, останов внутри типовой функции `ПродажиСервер.ПроцентПрироста` и hot reload её локальной копии. Период определяется по последнему активному движению выручки в выбранной ИБ; дата её данных заранее не предполагается. Метаданные и оба запроса сверены через EDT. 14.09.2026 все ячейки выполнены на временной копии файловой ИБ, включая hot reload; обе диаграммы проверены.

Сценарии ЗУП рассчитаны на выделенную демобазу **ЗУП КОРП 3.1.38.92**, платформу **8.5.1.1529** и выгрузку исходников этой же конфигурации. Дата данных в примерах — **01.08.2021**; это не номер релиза. 14.09.2026 все ячейки текущих `01-overview` и `03-capture` выполнены на независимых временных файловых копиях ИБ с пакетом 0.1.19 из PyPI, включая hot reload, остановы и повторное проведение документа в обзоре. Результаты выполнения остаются локальными и не входят в репозиторий.

Для установки из PyPI и запуска в VS Code используйте [«Быстрый старт»](../../README.md). Для работы с исходниками проекта и JupyterLab из корня репозитория установите окружение и зарегистрируйте kernel:

```powershell
uv sync --group dev
uv pip install --python .venv/Scripts/python.exe "jupyterlab>=4.1,<5" "matplotlib>=3.11,<4"
.venv/Scripts/python.exe -m ipykernel install --user --name onec-demo --display-name "1C BSL Demo"
.venv/Scripts/python.exe -m jupyterlab notebooks/demo
```

В стартовой Python-ячейке каждого notebook задайте `PLATFORM_BIN`, `CONNECTION_STRING` и `SOURCE_ROOT` для своей демобазы. Если в ИБ есть пользователи, задайте нужные `username` и `password` в `RuntimeConfig` локально. Для финального capture в обзоре нужен `CommonModules/РасчетЗарплатыРасширенный/Ext/Module.bsl` из выгрузки той же версии; для `03-capture` — `CommonModules/КадровыйУчет/Ext/Module.bsl`, для УТ — `CommonModules/ПродажиСервер/Ext/Module.bsl`. Если выгрузка отличается, сверьте номер строки в `runtime.add_capture_point()`.

Для файловой и клиент-серверной ИБ по умолчанию используется `EXTENSION_MODE = ExtensionMode.AUTO`. Если в ИБ уже есть точная версия расширения из этого релиза, runtime сначала проверяет её при запуске клиентского и серверного сеансов и не подключается к Configurator Agent. Если расширение отсутствует, устарело или проверка запуска выявила проблему, автоматической установке или исправлению требуется подключение к Configurator Agent с учётной записью ИБ. Для расширения, установленного вручную с отключённым «Безопасным режимом», используйте `ExtensionMode.MANUAL`, как показано в [«Быстром старте»](../../README.md).

`03-capture` и сценарий УТ читают данные ИБ; обзорный `01-overview` повторно проводит выбранный документ и меняет данные демоснимка. Для hot reload меняйте только локальную копию выгрузки исходников: сохранённый BSL-модуль загружается в текущий сеанс без изменения конфигурации ИБ. Используйте временную копию ИБ. Последняя ячейка вызывает `runtime.close()`; после прерванного прогона вызовите его вручную перед новым запуском.

Исходные ячейки всех трёх notebooks находятся в `tools/build_demo_notebooks.py`. После изменения генератора выполните `uv run python tools/build_demo_notebooks.py` и проверьте, что сохранённые notebooks не содержат outputs.
