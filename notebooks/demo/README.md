# Демо Jupyter для ЗУП КОРП и УТ

[01-overview.ipynb](01-overview.ipynb) показывает выбор сотрудников, плановый ФОТ, одну точку останова и hot reload типового метода. [03-capture.ipynb](03-capture.ipynb) исследует временную таблицу и стек вызовов между двумя точками останова, затем меняет локальный запрос только в одном вызове. Каждый notebook запускается сверху вниз в отдельном kernel.

[05-ut-sales.ipynb](05-ut-sales.ipynb) — отдельный сценарий для **УТ 11.6.1.61**: сравнение месячной выручки из регистра «Выручка и себестоимость продаж», диаграммы по подразделениям и останов внутри типовой функции `ПродажиСервер.ПроцентПрироста`. Период определяется по последнему активному движению выручки в выбранной ИБ; дата её данных заранее не предполагается. Метаданные и оба запроса сверены через EDT. 14.09.2026 notebook полностью выполнен на временной копии файловой ИБ; обе диаграммы проверены.

Сценарии ЗУП рассчитаны на выделенную демобазу **ЗУП КОРП 3.1.38.92**, платформу **8.5.1.1529** и выгрузку исходников этой же конфигурации. Дата данных в примерах — **01.08.2021**; это не номер релиза. 13.09.2026 оба notebooks ЗУП прошли сверху вниз на файловой и клиент-серверной демобазах. На файловой ИБ использовался `ExtensionMode.AUTO`, на серверной — `ExtensionMode.MANUAL` с уже установленным совместимым расширением. 14.09.2026 оба notebooks повторно выполнены на временных копиях файловой ИБ. При проверке hot reload менялась только отдельная локальная копия двух BSL-модулей; исходная выгрузка не менялась. Результаты выполнения остаются локальными и не входят в репозиторий.

Из корня репозитория установите окружение и зарегистрируйте kernel:

```powershell
uv sync --group dev
uv pip install --python .venv/Scripts/python.exe "jupyterlab>=4.1,<5" "matplotlib>=3.11,<4"
.venv/Scripts/python.exe -m ipykernel install --user --name onec-demo --display-name "1C BSL Demo"
.venv/Scripts/python.exe -m jupyterlab notebooks/demo
```

В стартовой Python-ячейке каждого notebook задайте `PLATFORM_BIN`, `CONNECTION_STRING` и `SOURCE_ROOT` для своей демобазы. В примерах ЗУП указано имя пользователя `Савинская З.Ю. (Системный программист)` с пустым паролем; для УТ укажите нужные учётные данные локально, если в ИБ есть пользователи. До запуска capture убедитесь, что `SOURCE_ROOT` содержит `CommonModules/КадровыйУчет/Ext/Module.bsl` для ЗУП или `CommonModules/ПродажиСервер/Ext/Module.bsl` для УТ из той же версии конфигурации. Номера строк точек уже указаны в notebooks для этих версий; если ваша выгрузка отличается, сверьте и измените номера в вызовах `runtime.add_capture_point()`.

Для файловой ИБ по умолчанию используется `EXTENSION_MODE = ExtensionMode.AUTO`. Если в клиент-серверной ИБ расширение из этого релиза уже установлено и применено вручную, задайте `EXTENSION_MODE = ExtensionMode.MANUAL`: это позволяет начать сеанс без учётных данных Конфигуратора для автоматического обновления расширения. Режим `MANUAL` проверяет совместимость расширения при запуске.

Сценарии читают данные и меняют только состояние интерактивного сеанса. Используйте отдельную копию ИБ: установка runtime-расширения меняет её служебные данные. Последняя ячейка вызывает `runtime.close()`; после прерванного прогона вызовите его вручную перед новым запуском.

Исходные ячейки всех трёх notebooks находятся в `tools/build_demo_notebooks.py`. После изменения генератора выполните `uv run python tools/build_demo_notebooks.py` и проверьте, что сохранённые notebooks не содержат outputs.
