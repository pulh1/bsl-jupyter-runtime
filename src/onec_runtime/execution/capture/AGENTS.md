# CAPTURE scope and execution

Design authority: [MAIN/CAPTURE execution spec](../../../../docs/superpowers/specs/2026-09-17-main-capture-execution-design.md), sections 5–9.

`scope.py` records one recognized stop, frame/setup evidence, dirty roots, writeback ledger, temporary cleanup debts and release. `executor.py` performs ordered stop setup; `cell_evaluator.py` and `operation_executor.py` execute a cell; `inspection.py`, `materialization.py`, `writeback.py` and `stack.py` own their focused CAPTURE capabilities. `policy.py` and `preparation.py` select CAPTURE lowering. Public `RuntimeSession.start()` composes these through one controller and arbiter.

- The controller creates one `CaptureScope` per recognized stop before staged setup. Multiple CAPTURE cells share it. The scope owns identity, setup evidence, dirty-root/writeback state and temporary-key debts; the controller pins the active Worker generation per CAPTURE cell ticket while the suspended MAIN command retains its own pin. The spec's broader scope-owned resource-debt model has not moved those pin leases; do not add a parallel scope ledger. The scope must not duplicate the arbiter's pending protocol capability. A confirmed temporary-key deletion failure can be retried by `submit_capture_cleanup_retry` without repeating admission or payload; an unknown deletion outcome needs reconciliation first. Neither fact alone loses the frame.
- `CaptureCellPreparer` and `CaptureCellPolicy` own the lowering profile, message key, dirty roots and route-specific preparation/settlement contracts. Public composition binds speculative MAIN names, confirmed namespace publication, Worker activation/pins and message collection. The controller runs setup, cell eval, variable reads, materialization, temporary cleanup retry, dirty-root writeback and resume through the arbiter port. `CaptureSetupAdapter` and `CaptureCellEvaluator` use bounded transport intervals without a BSL execution deadline. `data_plane.py` reads saved stack and private ticket results; `public_inspection.py` binds stopped stack/frame/context handles; `value_projection.py` exposes bounded variable names and selected opaque metadata. Top-level bounded table projection is public; nested columns remain unsupported. `ticket_materialization.py` and `dynamic_value_materialization.py` submit qualified direct and bounded projection plans through controller tickets.
- Revalidate remote frame identity and the local route fence before dispatch. An unchanged location after ambiguous Continue is insufficient evidence of the same stopped frame. Pending or unknown evaluation blocks dependent requests until settlement or confirmed teardown; it does not block read-only status or independent Python execution.
- A confirmed BSL, Worker, inspection or materialization failure ends that request without proving frame loss. Track cleanup/pin/breakpoint debts separately and block the affected capabilities. Setup failures retain known identity evidence and readiness progress; do not manufacture a second mutable CAPTURE lifecycle in the API.
- Trusted Worker publication on a confirmed CAPTURE frame uses the same `stage_batch`/`prepare_root`/`swap_root` mutation protocol as MAIN, but evaluates each instruction through `ВыполнитьКодВКонтекстеОтладки` on the CAPTURE frame. It must not write the suspended MAIN command fields or issue `Continue`; unknown eval keeps its arbiter ticket and any exact pending capability for reconciliation.
- Root writeback happens only during resume. Record confirmed, failed and unknown root writes separately; never blindly repeat an unknown write or Continue. CAPTURE is not a transaction: confirmed partial writes and arbitrary BSL side effects cannot be rolled back by restoring Python state.
- The controller admits explicit dirty roots and successor capture locations in one resume ticket. It installs successor breakpoints before writeback and Continue. A retry within the same resume attempt uses the frozen writeback ledger and cannot add new roots. A full successor-admission rollback after a confirmed export-only failure may discard that ledger only after proving no frame root reached `modifyValue` and restoring the prior breakpoint workspace; the CAPTURE scope then admits cells again while retaining its dirty-root names.
- The owner retains pending evaluation and cleanup duties after waiter detachment. Stop fences active work and schedules exact-target termination when remote effects remain unresolved; no cancellation success or preserved frame may be claimed without evidence. There is no BSL execution deadline, though individual network requests remain bounded.

Target contracts are `PreparationContext`/`PreparedCell`, `CellPolicy`, the CAPTURE capability port and arbiter tickets/fences. Public `CaptureFence`, `CaptureStatus` and `CaptureView` carry bounded, redacted stop evidence. A confirmed setup failure reports `capture_setup_failed` with stage evidence; admission remains blocked because RDBG has no remote stop nonce that can rule out an external Continue and repeat stop at the same location. A safe retry needs stronger same-stop evidence.
