# Tests and fixtures

Keep synthetic 1C sources under `fixtures/onec`, acceptance notebooks under `fixtures/notebooks`, and the pinned parser-generator source under `fixtures/parsergen`. The small `fixtures/waterfall` set contains only files used by its regression verifier; do not add full live-run directories or process transcripts. A test fixture must be self-contained and free of personal data. Change a generated notebook's builder first, regenerate the checked-in file, then run `--check` for `tools/build_jupyter_bsl_fixture_notebook.py` or `tools/build_zup_worker_universe_notebook.py`. Demo notebooks use `tools/build_demo_notebooks.py` without `--check`.

Unit tests should run without a 1C installation unless explicitly marked otherwise. Start with focused behavior tests, then use `uv run python -m pytest tests/unit -q` for the offline suite; neither proves live behavior. Live tests in `integration/` are opt-in, require their specific environment flag and an installed platform, use a disposable infobase, and record evidence outside the repository. Prefer a focused behavior test over assertions that merely mirror implementation text.

The ZUP Worker universe notebook is a full live acceptance scenario only after exact reference preflight and observed MAIN/CAPTURE semantic gates, performance samples and cleanup pass. A static notebook check, mocked runner, skipped live gate, or `incompatible_prerequisites` result is not a live `PASS` or an SLA claim. Preserve the 60 measured / 3 warmup sample contract and privacy-safe compact evidence when changing that workflow. Report precisely which opt-in live gates ran.
